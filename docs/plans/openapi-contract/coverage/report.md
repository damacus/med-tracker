## Remaining gaps and limits

- **Implementation:** 89 documented method/path pairs still have no Rust route. Their identities remain in `operations.jsonl`. The eight location routes are partial, not complete contract coverage; individual untested statuses and constraints are in `test-evidence.json`.
- **Untested route behaviour:** 21 other route matches have no spec-traced runtime assertion. Among location methods, auth variants, conflict cases, malformed membership bodies, and 429 plus `Retry-After` remain untested as listed per operation.
- **Specification ambiguity:** “visible locations”, “managed person”, and “retained history” do not specify role, person-grant, or deletion rules. Owner-only mutation is an interim restriction and does not establish intended role parity or complete deletion behaviour. The spec documents 429 and `Retry-After` but no threshold or trigger. Wrong-household status is not pinned down by the spec. The user has been asked to resolve these questions before full acceptance.
- **Outside this API specification:** Rails and Leptos behaviour were not used to define expected API results. The existing database schema and fixture SQL only provisioned isolated test records. No Rails or UI code was changed.

The isolated runner still rebuilds broad API and contract-test sources. Its cost is a tooling follow-up; it did not narrow the spec-derived assertions.
