# External integrations: final three fixed-118 API operations

The root OpenAPI document defines the response shapes and the Rails application defines the compatibility reference. This batch covers only `searchMedicationLookup`, `generateAiMedicationSuggestions`, and `testPushSubscription`.

## Acceptance

- Medication lookup authenticates and authorises the household request, returns empty results with permission flags when `q` is blank, and searches barcode sources in the configured priority: imported catalog, local dm+d, cached Open Products Facts, live Open Products Facts, and curated products. It then uses NHS dm+d and Open Food Facts barcode or supplement search as Rails does. NHS obtains an OAuth client-credentials token and requests VMP and AMP `ValueSet/$expand` results with `filter` and `count=20`. Results include imported trade-family metadata, visible related medication records, and matched review evidence; form and strength filters apply before enrichment. An unavailable provider returns the documented 503 shape. Every authorised outcome has a request-linked audit event, and provider attempts create hashed-query business audit rows without raw medicine text.
- AI suggestions authenticate and authorise the household request, enforce the paid feature gate before using a provider, and accept only the seven identity fields in `AiMedicationIdentity`. Unknown fields fail validation. With no configured model or API key, the 200 draft has empty medication, doses and sources plus a safe configuration error. OpenAI and OpenRouter use their chat completion protocols; Anthropic uses Messages; Gemini uses `generateContent`. A configured provider must be selected unambiguously and match its key and model. The source step selects configured seeds or proposes candidate URLs, fetches only allowlisted HTTPS port 443 URLs without following redirects, and passes fetched text to the model. The shared validator accepts only source URLs actually fetched by this request, normalises numeric dose fields, and checks that dose amounts, limits, intervals, cycle terms, and warning text occur in the fetched evidence; no fetched evidence yields no clinical draft. Every authorised outcome has a request-linked request audit and hashed-identity business audit.
- Push test authenticates and authorises the account, sends the Rails test title/body/dashboard path to web subscriptions as encrypted Web Push with VAPID and to configured native FCM/APNs tokens, and returns an empty 204 after delivery attempts. Only permanent invalid or expired web subscriptions and unregistered native tokens are deleted. A sender-level web configuration failure returns `push_test_failed` 503 with a request ID after independently attempting native delivery; native-only accounts do not require VAPID keys. A web endpoint must pass the existing push allowlist; an internal fake origin is reachable only through an explicit exact trusted origin configuration.

## Provider boundary

The Rust API owns outbound adapters in a new module. Its HTTP client has a finite timeout and does not follow redirects. NHS URLs come from validated application settings, with production HTTPS defaults. AI URLs default to each provider API and are configurable only as explicit trusted service settings for isolated tests. Web Push uses a standards-based Rust library for RFC 8188 encryption and VAPID; the internal fake receives its actual HTTP request and checks encrypted bytes and signing headers. Native fakes receive FCM HTTP v1 JSON and APNs `/3/device/{token}` requests, including provider authentication. Tests never call live providers. Separate lookup, AI, and push failure paths keep errors and audit outcomes independent.

The contract runner supplies a deterministic internal HTTP fake for each provider. Compiled black-box HTTP tests must fail against the current Rust API before implementation, then exercise the built Rust process. Rails provider doubles alone do not satisfy this gate.

For AI, a source fetch that fails, redirects, or finds no allowlisted page returns `{medication: {}, doses: [], sources: [], errors: ["trusted_source_unavailable"]}` inside `data`. A model output with an allowlisted but unfetched URL has that source and any dose linked to it removed. The isolated runner sets one provider, model, and key on each of four API instances and checks each provider's request protocol against an internal fake.
