# Account session contract tranche

Base `c92cb86a`. Source operations: `listSessions` (`#/paths/~1auth~1sessions/get`), `deleteSession` (`#/paths/~1auth~1sessions~1{id}/delete`) and `logoutSession` (`#/paths/~1auth~1logout/delete`). The Rust API has no matching routes. `AuthSessionCollectionResponse` requires exact `data` and each `AuthSession` requires ID, device name, last use, access expiry, refresh expiry, creation time, with optional household ID. DELETE success has no body.

Existing account-session behavior is in `app/controllers/api/v1/auth/sessions_controller.rb`: API sessions and app tokens list/revoke account API sessions; mobile OAuth credentials list/revoke mobile grants; logout revokes a recognized API session, app token or OAuth grant and is an idempotent 204 for unknown credentials. Nonrevoked API sessions remain listed even if their access or refresh credential has expired. Expired credentials cannot authenticate a new request. Document credential-class and expiry details in OpenAPI before deriving RED tests. Use disposable credentials in the isolated database so revocation tests cannot damage shared fixture credentials.

Test first: exact schema and no credential leakage, own account and active-only filtering, selected session revocation and cross-account 404, current session/app-token logout with durable revocation, invalid/expired/revoked auth, and empty 204. Then implement SeaORM-backed account authentication and writes, run one isolated RED and a consolidated GREEN, and update per-operation evidence without marking untested variants complete.
