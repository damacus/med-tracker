# Current-chat retrospective

Evidence: this conversation, agent handoffs, and integrated code through
`7bec286a`. This is a qualitative review; elapsed-time and token-cost totals
were not reconstructed.

## What worked

Behavioural tests and independent review found decimal serialization,
unbounded delegated-ID queries, timezone, representation ETag, and missing
304 audit issues. The integrated medication slice passed 12 focused HTTP
cases and three unit tests. Restricted-role PostgreSQL checks preserved the
authorization boundary. Reports correctly separated source audit rows from
unverified ledger append, and debug idle memory from workload proof.

## What slowed delivery

Inventory expansion delayed working Rust functionality. The orchestrator
became a writer, runner, reviewer, and integration bottleneck. Separate
feature worktrees still edited the same runtime and documentation files,
causing predictable integration conflicts. A fixed acceptance port serialized
HTTP checks; each disposable run repeated fixture startup. Repeated checks
were not always tied to a new risk. Agent model selection was insufficiently
explicit for the user's speed and cost priorities.

An observed Rails conditional-request defect was initially treated as
behaviour to preserve. The user corrected that interpretation. The Rust
regression now targets intended behaviour. Future defect decisions must make
this distinction before tests become acceptance criteria.

## Skill and agent effectiveness

Bounded implementation agents and independent reviews produced useful code
and caught issues. Their ownership boundaries were too broad where several
agents owned shared files. Applying ordinary subagent execution and persistent
team rules together would add conflicting ownership instructions. This run
uses team-development with an explicit user override for separate test and
product writers. Sol handles authentication judgment; Luna handles objective
execution and bounded inventory. The root owns consequential interpretation
and acceptance rather than routinely writing all layers.

## Changes for this run

Use the project charter, disjoint test/product ownership, a pipelined red-green
handoff, and independent read-only verification. Share the checkout when file
ownership is sufficient. Serialize only conflicting test resources. Record
verification against stable inputs and report limitations once in the ledger.
Assess improvement by accepted behaviour and rework, without inventing speed
or cost savings. Global skill changes require a separate agreed edit.

The user's follow-up emphasized time taken and the angle of attack. The
delivery unit will therefore be a usable journey rather than an inventory
category. Finish the active OAuth dependency, then progress toward viewing a
medication, recording a dose, and observing updated stock/history. Track time
in preparation, execution and rework so further workflow changes address
observed delays.

The user also corrected treating port 39998 as a resource constraint: the
existing database isolation should extend to API and HTTP-test containers on
the same per-project network. The orchestrator should have challenged the
host runner design earlier. A bounded tooling lane now addresses that cause;
assigning arbitrary host ports would leave the architectural mistake intact.
