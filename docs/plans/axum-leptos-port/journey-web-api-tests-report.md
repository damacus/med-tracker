## Cookie denial audit assertion

Each authenticated cookie dose POST rejected for missing or wrong CSRF, absent origin evidence, or hostile Origin now must emit one `api.request` failure event keyed by its response request ID. The test checks household, account, membership, method, action and 403 status, and rejects bearer, signed cookie, session CSRF, client UUID or source ID in that event. The existing zero-take and unchanged-stock assertions remain in place. `task contract:fmt`, `task contract:clippy`, and `git diff --check` passed after this focused test edit; the new assertion has not had a real acceptance run.

The primary fixture account already has a second active household membership. A cookie read there now checks that the request audit uses that household's current membership while retaining Rails' deterministic primary `Account#person.user` as actor. A separate disposable test temporarily links an active second person/user in the other household, then deactivates the primary user. Copied-cookie API requests to both households must return 401 and the authenticated dashboard must redirect to login; the second active user cannot bypass the primary actor rule. The setup restores the primary user and membership link and removes its temporary rows on drop. This is a source-corrected expectation following Rails account identity review, not a household-specific actor switch. Formatting, Clippy and diff checks passed; no real acceptance result for these additions yet.

A focused sliding-session case now requires both dashboard and cookie-authenticated medication API reads to reissue the same signed session cookie with a positive, bounded `Max-Age`. The dashboard must retain the session CSRF token, which the test then uses to log out. An explicit invalid bearer must not renew the cookie; logout must emit only the expired session cookie and reject a copied pre-logout cookie. This avoids timer sleeps or another fixture family. The case has not yet had a real acceptance run.
