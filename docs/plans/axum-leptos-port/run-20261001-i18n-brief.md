# Household i18n implementation brief

Owner: i18n agent. Root owns manifests, module registration, Task commands and locale source edits. This agent owns household_i18n.rs, its focused integration tests and the three run i18n documents.

## Bounded outcome

Provide an explicitly selected locale and validated authoritative catalogue text for new household UI. Support en, cy, ga, es and pt. Preserve exact-zero/one/other semantics and English fallback. No global locale state, invented translations or dashboard/search rewrite.

## First proof

Write failing tests before production implementation. Root supplies module registration and a Task test command. Request leptos_i18n/leptos_i18n_build exactly 0.6.2 for a bounded SSR manual render compatibility proof. Root owns build generation; if that proof cannot complete quickly, record the evidence and use a tiny typed catalogue adapter. The crate is uncached and DNS unavailable, so root explicitly authorised the cached serde_yaml 0.9 transitional parser. Its deprecated maintenance status must remain visible in the report.

## Helper contract

Locale is a five-variant enum with an allowlisted parser and cookie/header/English resolver. Text takes Locale explicitly, retrieves only declared household keys, interpolates named arguments and selects the existing zero/one/other branches. Missing required English keys, unsupported value shapes and missing interpolation values return errors. A missing non-English key may use English only with explicit observable fallback metadata. Locale/time-zone/date-format policy remain separate.

## Verification

Focused Task tests cover five-locale strings, interpolation, exact-zero/plural output, invalid/weighted/regional locale resolution, missing-key/fallback behaviour and SSR escaping. Required page owners wire the helper and verify actual browser rendering. No production helper before the focused failing test is recorded. No comments, commits or pushes by this agent.
