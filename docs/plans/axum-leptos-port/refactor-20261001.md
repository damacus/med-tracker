# Rust maintainability review

Dan's personal review identified `read_resources.rs` as too large to navigate and
edit safely. The audit also found resource handlers, authentication, browser
orchestration and test infrastructure mixed in other files changed by PR #2346.
This follow-up preserves behaviour and existing imports while separating those
responsibilities. No dependency, API, database or deployment change is planned.

## Ownership and placement

| Existing file | Lines before | Lines after | Responsibility split |
| --- | ---: | ---: | --- |
| `rust/api/src/read_resources.rs` | 1390 | 13 | Resource endpoints, response handling, source projection and eligible stock |
| `rust/api/src/people.rs` | 1499 | 14 | Access, validation, persistence and person actions |
| `rust/api/src/locations.rs` | 2164 | 19 | Location actions, access, validation, persistence and cascade handling |
| `rust/api/src/medication_management.rs` | 2003 | 22 | Medication actions, dose mode, access, validation and persistence |
| `rust/api/src/web_pages.rs` | 1747 | 84 | Assets, cookie API client, HTML responses, inventory, dashboard and dose submission |
| `rust/api/src/lib.rs` | 1351 | 131 | Router composition, authentication, request guards, API responses and medication reads |
| `rust/contract-tests/src/lib.rs` | 926 | 5 | Fixture schema/loading and HTTP transport with local-write protection |
| `rust/web/src/lib.rs` | 612 | 108 | Authentication, shared document wrapper and medication rendering |

Keep each resource's implementation beneath its existing module. New actions
belong with that resource, rather than in a global helpers folder. Keep browser
transport and rendering in their existing separate crates. Root modules expose
explicit existing entry points; sibling modules use only the interfaces they
need. Dependencies remain within the existing crates and compiler visibility
protects those interfaces.

The read-resource entry points keep their existing names. Their implementation
now has this shallow shape:

```text
rust/api/src/
├── read_resources.rs                 explicit existing exports
└── read_resources/                   private resource implementations
    ├── people.rs                    person reads and representation
    ├── locations.rs                 location reads and representation
    ├── schedules.rs                 schedule read endpoints
    ├── assignments.rs               assignment read endpoints
    ├── source_projection.rs         batched schedule/assignment representation
    ├── source_stock.rs              permitted matching stock sources
    └── response.rs                  pagination, audit and HTTP responses
```

The audit found the remaining household renderers, locale adapter, capability
endpoint and OTP compatibility helper cohesive. Generated code and unrelated
legacy modules are outside this change. A universal line limit, new crate per
resource and generic request builders were rejected: they would add churn or
hide deliberate authentication/header differences.
