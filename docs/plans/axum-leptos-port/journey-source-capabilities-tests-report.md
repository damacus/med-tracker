# Source capability API test report

`rust/contract-tests/tests/source_capabilities_api.rs` is a new Rust-only HTTP contract for additive `can_record` and `eligible_stock_medication_ids` fields on existing schedule and person-medication collection/detail rows. These fields are not part of the current Rails JSON response, so this target is not a Rails JSON parity comparison. Existing source read and dose-write tests remain selected separately.

The permission case reuses the owner and view-only fixture credentials. It requires owner `can_record=true`, viewer `can_record=false` with no actionable stock, and a temporary viewer grant changed from `view` to `record` to prove `can_record=true` while `can_manage=false`. It also requires a paused source to retain record permission but expose no currently actionable stock. The temporary grant restores its original level on drop.

The stock case reuses the seeded direct assignment, schedule, alternate medication and tracked dosage. It requires exact medication name, dose amount and unit, a positive supply sufficient for the 1.25 ml dose, and deterministic location-name then medication-ID ordering. A temporary same-signature candidate is moved between existing locations and varied across mismatched dose, mismatched unit, zero supply and insufficient supply. A hidden person's matching medication is visible as a choice to the owner but excluded for a record-only viewer of the source person. Temporary medication values and the viewer's grant restore on drop. The tracked option is temporarily reduced below one dose and restored on drop. The underlying POST remains the final authority for timing and concurrent stock changes.

The canonical medication API test script now appends only `source_capabilities_api` and preserves `--no-fail-fast`; no separate harness is needed. `task contract:fmt`, `task contract:clippy`, and `git diff --check` passed. No production file changed in this lane. A live field-missing RED remains pending after the test setup correction.

The first canonical run passed 52 of 53 selected tests. The remaining capability case stopped in its temporary stock setup before checking the API: PostgreSQL rejected a Rust string bound directly to a numeric parameter. All three temporary numeric setters now cast through text before numeric conversion, matching their existing restoration queries. Formatting, Clippy and diff checks passed after the correction; the 53-case rerun is pending.
