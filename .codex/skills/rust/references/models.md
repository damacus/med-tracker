# Model routing

This guidance selects capability; it does not authorise delegation or silently
change the active model. Use only models and efforts exposed by the runtime.

| Model | Appropriate work |
| --- | --- |
| Luna 6 | Established page/form pattern, bounded projection or test cases with explicit behaviour and objective checks |
| Sol 6.1 | Unfamiliar Rust path, Rails parity discovery, shared components, local design, crate evaluation and ordinary independent review |
| Astra 6 | Unresolved authentication compatibility, tenant isolation or transaction races, and consequential cross-boundary design where deeper judgement is needed |

Route by uncertainty, consequence and the strength of verification, not file
count. Luna can complete a clear journey; Sol does not need an automatic Astra
review. Do not escalate merely because a task involves Rust.

Keep the user's reasoning choice or the runtime's documented default. Increase
effort when the model has a sound explanation but needs more reasoning on a
bounded problem. Change model when judgement is missing. Reassess after two
evidence-based attempts leave the same failure unexplained, or when access,
data compatibility or concurrency exposes a new consequential decision.

For routing decisions involving allowance, resets or handoffs, use the existing
adaptive-model-routing skill rather than duplicating its policy here. This
reference introduces no timer, agent team or mandatory extra review.
